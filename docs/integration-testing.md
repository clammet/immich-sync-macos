# Signed integration validation

Use a disposable Immich account and library for these checks. They are required before distributing a release; unit checks cannot establish system extension behavior.

1. Build both targets with matching provisioning, App Group, and Keychain access. Install the app, register a domain, enable the extension, and confirm a location appears in Finder. Relaunch the app and extension and confirm the same account and domain return.
2. Confirm an initial listing creates online-only entries without downloading every original. Open a JPEG, HEIC, RAW image, and a video. Compare downloaded hashes with their originals.
3. Pin a file and an album using Always keep available. Confirm downloads complete, new children inherit the policy, and files open without a network connection. Switch to on-demand availability and use Remove Download. Confirm pending edits and ignored files cannot be evicted.
4. Drop a PDF and another unsupported type beside supported media. Confirm the grey ignored overlay and accessibility label, no server upload, and local content survival after restart, refresh, offline operation, and album removal. Edit and delete the ignored files; no server mutations should occur. Check a nested directory, a package, and a symlink without traversing the latter two.
5. Upload duplicate media and large videos. Interrupt networking and quit the extension during upload; retry and confirm server deduplication. Verify failed uploads remain local. Exercise quota exhaustion, HTTP 413, expired keys, missing permissions, and server downtime.
6. Edit a photo from Finder. Verify the new original, copied memberships, old asset in Immich trash, and provider identity reconciliation. Kill the extension after upload, after copying associations, and after trashing; confirm retries preserve content and do not create avoidable duplicates.
7. Concurrently modify or delete the source through Immich while editing locally. Confirm the local edit is retained, conflicts are reported, and the client never force-deletes either original. Disable server trash; edits and library deletions must stop before deleting the old asset.
8. Create, rename, and remove album folders. Move photos between albums and into All Photos. Delete an album appearance and confirm the original remains. Delete from All Photos and confirm the original and every album appearance leave Finder while the asset remains in Immich trash.
9. Make remote additions, trash/restore assets, and change album membership while paging a large listing. Confirm eventual convergence without partial-snapshot deletion. Test all stack members, archived assets, locked assets, and read-only external-library assets.
10. Pause/resume, rotate the API key, test login startup, and disconnect with pending supported uploads and local-only files. Verify preserved user data is revealed in Finder. Confirm the app does not delete server originals during disconnect or registration repair.
11. Run on a second supported macOS release. Verify download-policy inheritance, the ignored badge at different Finder icon sizes, file-provider error recovery, VoiceOver labels, dark appearance, and menu bar transfer progress.
12. Archive and notarize a Developer ID distribution, install it on a clean Mac, and repeat registration, Keychain sharing, Gatekeeper, and login-startup checks.
